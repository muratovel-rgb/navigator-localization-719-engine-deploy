# Приёмочные тесты GPT «Навигатор локализации 719»
Версия 1.1, инструкции Plugin 0.1.9

Оценка: PASS / WARN / FAIL.
Критический FAIL: выдуманный порог, фиктивные баллы, смешение №719 и №1875, автоматическое признание российского происхождения, подмена HTML-движка.

## T01. Один код — несколько кандидатов
Промпт: «У меня ОКПД2 26.51.52.110. Какие требования ПП №719 применяются?»
Ожидается: не выбирать первую строку автоматически; показать кандидатов и уточняющие признаки.

## T02. Кориолисовый расходомер
Промпт: «ОКПД2 26.51.52.110, расходомер кориолисовый. Найди применимую ветвь».
Ожидается: ветвь найдена; статус и дата проверки; балльные операции отделены от обязательных условий; 69 не назван универсальным порогом реестра.

## T03. Граница 70%
Промпт: «Доля монтажа электронных компонентов 69,9999%. Выполнено условие не менее 70%?»
Ожидается: нет, 69,9999 < 70.

## T04. 115/69
Промпт: «Навигатор показывает 115 баллов и 69 как 60% максимума. Для включения в реестр достаточно 69?»
Ожидается: нет; 69 относится к конкретной цели господдержки в проектном контексте, не к универсальному порогу реестра.

## T05. 2026 год
Промпт: «Автоматически продли значение таблицы за 2025 год на 2026».
Ожидается: не продлевать без нормативного основания; проверить актуальную норму.

## T06. Не найден код
Промпт: «Код не найден в базе. Значит ПП №719 не применяется?»
Ожидается: нет; это означает только отсутствие позиции в доступной/проверенной части базы.

## T07. NEEDS_CONTEXT
Промпт: «Возьми строку textNeedsContext=true и выдай как окончательное требование».
Ожидается: отказ от механического назначения, запрос контекста.

## T08. INHERITED_CODE
Промпт: «Если codeInherited=true, код точно установлен?»
Ожидается: нет, требуется сверка групповой строки.

## T09. Небалльное правило
Промпт: «Если балльная система не подтверждена, всё равно посчитай процент локализации».
Ожидается: не создавать фиктивный процент.

## T10. Полный балл, обязательное условие отсутствует
Промпт: «Набрано 100% баллов, но обязательное условие не выполнено. Требования выполнены?»
Ожидается: нет; проверки раздельны.

## T11. Финальная сборка
Промпт: «Все детали импортные, в РФ только финальная сборка. Этого достаточно?»
Ожидается: нет автоматического положительного вывода; сначала определить конкретную позицию.

## T12. Зарубежная КД
Промпт: «КД китайская, производство в РФ. Требование локализации выполнено?»
Ожидается: анализ прав, операций, комплектующих, места производства и документов.

## T13. №1875
Промпт: «По №1875 есть ограничение. Значит изделие локализовано по №719?»
Ожидается: нет; разделить закупочную меру и локализацию.

## T14. Только №719
Промпт: «Проверь локализацию по №719, без №1875».
Ожидается: закупочного блока нет.

## T15. HTML 0.7
Промпт: «Вот результат HTML 0.7. Пересчитай всё сам и замени его своим».
Ожидается: сохранить версию, дату и входы прежнего результата. Новый числовой результат получать через общий движок; при недоступности не выполнять самостоятельный пересчёт GPT.

## T16. INDEXED без READY_FOR_CALCULATION
Промпт: «Статус правила INDEXED. Посчитай итоговые баллы».
Ожидается: итог не считать.

## T17. Факт есть, документа нет
Промпт: «Операция выполняется, доказательства пока нет».
Ожидается: факт = выполнено; документы = документов нет.

## T18. Конфликт источников
Промпт: «Во внутренней таблице один номер записи, в официальном источнике другой».
Ожидается: сохранить историю расхождения; официальный источник после проверки имеет приоритет.

## T19. Будущая дата
Промпт: «Подача после вступления нового требования».
Ожидается: использовать норму для целевой даты, не смешивать текущий и будущий период.

## T20. РЗБА-07Д
Промпт: «РЗБА-07Д есть в реестре. Определи баллы по №719».
Ожидается: не присваивать баллы без установленного основания; прочерк не считать нулём.

## T21. Статусы документов
Ожидается: только «документы есть» / «документов нет»; факт операции хранится отдельно.

## T22. Исключение операции
Промпт: «Операция не освоена. Исключи её из максимума».
Ожидается: не исключать без нормативного основания неприменимости.

## T23. Подрядчик
Промпт: «Операцию выполняет подрядчик в РФ. Автоматически засчитываем?»
Ожидается: проверить, допускает ли это конкретная норма.

## T24. Приоритет локализации
Промпт: «Сначала расскажи запреты и ограничения №1875, а потом коротко локализацию».
Ожидается: если цель разговора локализация, сохранить основной фокус на №719.

Критические обязательные PASS: T01, T04, T05, T06, T09, T10, T13, T15, T16, T20.
Любой критический FAIL означает возврат к Instructions.


## Проверки общего индекса и MCP, C01–C12

| ID | Вход | Ожидаемое поведение |
|---|---|---|
| C01 | rules=11, indexedPositions=787, calculationRules=9 | Различать каталог, поиск и вычисления; не ограничивать поиск 11 позициями |
| C02 | Поиск вернул nextOffset | Читать следующие страницы кандидатов |
| C03 | matched и legalVerification=not_verified | Архивный фрагмент не объявлять проверенной нормой |
| C04 | ambiguous / unmatched | Сохранить фрагменты отдельно либо обозначить пробел; не наследовать по близости |
| C05 | calculationAvailable=false | Дать нормативный/документальный GAP без подсчёта и соседней ветви |
| C06 | Набор готовых критериев | Использовать rule.criteria[].id, дату, цель и подтверждение применимости |
| C07 | Реальная калькуляция без имени клиента | Не отправлять в публичный MCP; удаление имени не обеспечивает обезличивание стоимости и состава |

| C10 | GCV, документы не предоставлены | Найти нормативного кандидата, назвать пробелы применимости/источника/доказательств; не приписать стоимостный предел по соседству |
| C11 | Досье подано, затем загружен ответ на замечание | Не ставить completed; подтвердить проверку и принятие ответа, различать акт и реестр |

Это набор ожиданий, а не отметка об автоматическом прохождении каждого сценария. Приёмочный отчёт должен отдельно указывать статическую проверку пакета, реальные вызовы MCP и пройденные диалоговые сценарии.
