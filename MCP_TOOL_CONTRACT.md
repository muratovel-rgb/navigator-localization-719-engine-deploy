# MCP tool contract for the ChatGPT plugin

## engine_health
Use before first calculation in a conversation when engine availability/version matters.

## search_localization_rules
Use only after the skill has narrowed the product by OKPD2/name/characteristics. Results include indexed positions and prepared calculation branches; distinguish calculationAvailable.

Never infer that absence from this tool means PP No. 719 does not apply.

## get_localization_rule
Call before collecting calculation facts. Use returned criterion IDs and requirements; do not invent criterion IDs.

## get_threshold_context
Call whenever the user asks how many points/what threshold is required for a date and purpose.

Do not infer a universal registry/localization threshold when the tool returns null.

## calculate_localization
Call only when:
1. a concrete prepared rule branch is selected;
2. legal applicability has been verified or explicitly marked as provisional;
3. `classificationConfirmed=true` only when the selected PP No. 719 position is actually confirmed;
4. facts are mapped to criterion IDs returned by `get_localization_rule`.

Treat the tool result as the Navigator 0.8 deterministic calculation result, not as an official legal determination of Russian origin.

If the tool result conflicts with the legal text or the skill's verified rule context, stop and report a candidate engine defect; do not silently overwrite either result.


## Additive response fields in service 0.3.0

- health: `calculationRules` and `unresolvedRules`; legacy `rules` remains all entries.
- rule: `foreignLimit`, `thresholdPolicy`, `periods`.
- criteria: `manufactureOrUse`, `originRequired`, `originTerritories`, `creditGroup`.

For an alternative criterion choose `route=manufacture` with Russian production facts, or `route=use` with `origin=rf` and an explicit `originBasis` where the rule permits only RF. EAEU residence or supplier country does not establish RF origin. Do not count the alternative twice. Purchasing or outsourcing does not remove an applicable operation from the maximum.

`applicableCriterionIds` is the complete set of included scored criteria. IDs must be unique scored criteria from this rule. This tool validates the set, not the technological evidence for exclusions. A numeric threshold uses that rule/date/goal. `null` is preserved for unassigned thresholds, including 2026 procurement contexts in the supplied measurement rules.

Tool names and calculation fact input keys remain unchanged. Live BOM transport remains unsupported until API-002 is separately released; the local candidate below does not change the live contract. Unresolved rules remain blocked.

## Prepared additive LNG selection transport (not deployed)

`calculate_localization` accepts optional `selection` with the existing assessment fields
`equipment`, `type`, `usage`, and `standard`, as strings up to 120 characters.
Omitted fields retain the engine's existing defaults. The shared engine owns accepted
values and applicability; neither the API schema nor the agent assigns new normative
rules. Missing or unsupported combinations remain blocked by the same engine.
When provided, the effective selection is echoed in `input.selection`; old calls
without selection retain the old response shape. This draft does not establish legal
applicability or permit real client data on the public Render endpoint.

This change is local preparation only. Release version/provenance, App discovery,
publication and actual deployed verification are separate gates.

## Full-index search in 0.4.0
Search results include indexed positions in addition to prepared calculations. Choose by code, purpose and characteristics. Use limit/offset and nextOffset to read all candidates. Use resultType and calculationAvailable; never treat every indexed ID as an implemented calculation. get_localization_rule accepts a prepared ID or indexed position ID and returns the exact indexedPosition text and provenance. A search miss does not establish absence in PP719. fullLegalCoverageVerified is false for this imported baseline.


## Archived context in 0.4.1
`requirementContext` supplements, and never replaces, `indexedPosition`. All structural matches are `legalVerification: not_verified`; `matched` concerns archived table structure only. Multiple matches are preserved as candidates, not merged into requirements. A complete text fragment is not a verified calculation rule. `calculate_localization` and thresholds do not consume this supplementary text. Five MCP tools and their input contracts remain compatible.

API-001 local release candidate: service 0.4.2. Engine 0.8.1 and normative/index release identifiers are unchanged because evaluation code and rule data are unchanged. This candidate has not been pushed or deployed. Final source commit and exact generated bytes are pinned in release-provenance.json.

## API-002 prepared transport contract (not published)

Optional top-level `bom` transports the existing assessment BOM array only when `costs.mode` is `bom`. Each line has exactly five required strings: `quantity` and `unitCost` up to120characters, `currency` up to16, `origin` up to32, and `originBasis` up to5000. At most500lines; limits reject instead of truncating. Names, supplier identities, attachments and arbitrary fields are not part of this calculation contract. A full UI BOM object must not be sent unchanged.

The existing overall HTTP request size limit of 1 MiB remains unchanged. It may reject a payload before the per-line count limits are reached. Existing rule method determines whether a cost result applies; supplying BOM does not add a cost rule to a points or unresolved branch.

Values are passed unchanged to existing engine.js. Currency, quantity, costs, unknown origin, completeness, denominator basis, applicable foreign limit and final status remain owned by the engine. No percentage/formula or legal rule is introduced by the adapter. Empty/incomplete BOM and missing facts remain engine unknown/invalid/blocked as before. A provided top-level list with another cost mode is rejected rather than silently ignored.

The input echo includes a defensive copy of the five-field list only if supplied. Omitting top-level bom preserves old valid input responses. Legacy nested `costs.bom` is not an alias and is not promoted into assessment.bom.

Privacy: this patch is local-only. Public Render remains public/synthetic-only; never send real client BOM, component prices or confidential references there. Private Site access is unchanged; this patch does not grant permission to migrate/import real data, extend audience, alter retention, or declare multi-client isolation. No logging/storage/auth changes. No document or supplier data are used in acceptance fixtures.

Release gates: exact version and source provenance, current GitHub/Render/Site bases, explicit publication approval, deployed schema checks and actual synthetic calls through supported host schemas. This functional patch alone is PREPARED, not a production release or legal acceptance.

API-002 exact local candidate targets service0.4.3 and Site protocol0.5.4-sites.1. Engine0.8.1 and normative/index release identifiers remain unchanged. This is not a live release. Source identity remapping through the existing GitHub connector, if later authorized, must preserve the exact covered source tree and regenerate only provenance references.
