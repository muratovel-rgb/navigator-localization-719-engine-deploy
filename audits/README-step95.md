# Шаг 9.5. Матрица требований, фактов и разрывов

Дата: 16.10.2026. HTML 0.9.2, существующая ветка sync/engine-08.

## Сверка подходов

Сохранены единый продукт, общий движок и существующий проектный контур. Основная последовательность: применимость требования → фактическое производство → доказательства → разрыв → действие → повторная проверка → пакет. Закупочный контекст остаётся дополнительным. Не создавались агент, сервис, репозиторий или отдельная CRM.

Досье 0.9.1 покрывало документы и сопровождение, но не давало единой записи требования и факта. Шаг 9.5 закрывает этот технический пробел, не активируя нормативный пакет №52 или новое числовое правило.

## Реализация

- requirement.record: условие, источник, точный пункт, редакция, дата ручной сверки, период применения, основание применимости, исполнения и связанные объекты происхождения.
- requirement.review: отдельно выполнение в производстве и достаточность документов; фактическое состояние, операция, место, исполнитель, основание и точные версии доказательств.
- requirement.action: способ устранения, ответственный, срок и необязательная связь с существующим дозапросом. Действие не заменяет проверку.
- Изменение документа, нормы/условия, исходных сведений проекта, связанного объекта или его предка требует повторной проверки. Чужой документ не переоткрывает независимый вывод.
- Период сопоставляется с датой оценки. Непроверенный источник, отсутствующие доказательства по части исполнений и непроверенная цепочка показываются раздельно. Иностранное сырьё не создаёт вымышленного универсального запрета.
- Пакет сохраняет тогдашнюю матрицу. Старые досье и пакеты без матрицы воспроизводятся в прежней форме.
- Интерфейс использует свёрнутый раздел и отдельные формы. Доступны выгрузка матрицы JSON и действия по разрывам в прежнем текстовом статусе проекта.

Источник и применимость могут быть отмечены пользователем как сверенные вручную. Это не повышает статус общего Rule Registry. Итог по строке означает только записанную внутреннюю проверку: полнота матрицы, нормативная готовность и официальное решение автоматически не определяются. Для проекта без калькулятора числовая ветвь не создаётся.

## Проверки

- 27 проверок модели матрицы: периоды, доказательства всех исполнений, независимые производственные/документальные разрывы, зависимости цепочки, прежние пакеты, перенос и отклонение подменённых данных.
- 12 новых DOM-проверок матрицы, всего 79 проверок собранного HTML. Проверены ввод, отдельные статусы, действия, экспорт, перенос JSON, ошибка записи и безопасное отображение текста.
- Прежние проверки движка, поиска, контекста, досье и аудита сохраняются. Числовой движок остаётся 0.8.1 с 9 ветвями.
- В прежнем сквозном DOM-тесте исправлена дата подачи: местная календарная дата вместо UTC. Повторены сценарии для UTC и Asia/Ho_Chi_Minh; дата сверки источника также учитывает местную дату.
- Нативная визуальная приёмка 0.9.1 остаётся историческим результатом. Новый раздел 0.9.2 в настоящем браузере в этом шаге не проверен. Счётчик 28 Chromium-проверок не переносится на новую версию.

## Оставшиеся вопросы

Реальное досье проверяется отдельно через разрешённый Drive, без помещения клиентских материалов в Git или общий HTML. Метаданные папок не являются доказательством содержания. Часть PDF не даёт читаемого текста и требует просмотра оригинала. Область распространения испытаний сверяется по первичному акту, а не по названию общей папки.

Повторный поиск официальных контрольных текстов №52/№64 и поправок №719 не закрыл прежнюю нормативную приёмку. Проверенные в правовых базах сведения не объявляются завершённой официальной сверкой. P01–P54 выключены; спорная дата №1297 и G11/G12 остаются открытыми. Production, Site и установленный Plugin не публиковались.

Следующие работы: первичные документы и охват реальных исполнений; контрольная нормативная сверка; визуальная приёмка новой матрицы; согласованный выпуск существующих компонентов.
