# Шаг 9.1 Досье ТПП и перенос проектов

Дата: 15.10.2026. Подготовлен HTML-предпросмотр интерфейса 0.8.2. Общий расчётный движок остаётся 0.8.1, нормативный выпуск localization-719-2026-10-14. Production не публиковался.

## Что сделано

Исходный интерфейс HTML 0.8 включён в существующий репозиторий в каталог web. Сборка build-web.py берёт движок, приборные данные, индекс и механизм досье из корня репозитория. Независимой копии расчётных правил в web нет. Закупочный модуль сохранён как вспомогательный, без изменения его критериев.

В карточку существующей оценки добавлен раздел досье ТПП:

- версии документов, контрольная сумма SHA-256, реквизиты/место хранения и перечень исполнений;
- замечания ТПП, внутреннего аудита и Минпромторга со ссылкой на вопрос P01–P54;
- отдельные события получения ответа и проверки содержания;
- внутреннее устранение, частичное устранение и повторное открытие;
- запись полученного внешнего решения с источником и версиями доказательств;
- история событий и сохранение состояния досье в снимке расчёта.

Выбранный файл читается локально для SHA-256. Содержимое файла не помещается в JSON и не отправляется на сервер. Сам файл нужно сохранять в используемом хранилище документов; в досье фиксируются его идентификация и место хранения. Внешнее решение является записью пользователя с указанным основанием, а не автоматической проверкой его подлинности.

При замене документа связанные замечания возвращаются на проверку. Предыдущая внутренняя проверка и внешнее решение остаются в истории с прежними версиями. Один документ не закрывает замечание по нескольким исполнениям, если его перечень исполнений их не покрывает.

## Импорт и сохранность

Формат JSON остаётся 2, досье добавляется как необязательное поле tpp52. Старые оценки без него принимаются. При совпадении ID и различии содержимого появляется выбор рабочей версии. Не выбранная версия сохраняется в importArchive независимо от того, предпочёл пользователь текущую или импортированную. Архивные оценки можно выгрузить.

Конфликт разных расчётных снимков с одним ID блокирует импорт. Исходные снимки не переписываются. Отмена, отсутствие выбора, некорректное досье, незнакомые новые поля и превышение лимитов не заменяют текущие данные. Запись в localStorage выполняется до замены рабочего состояния в памяти.

Если прежнее локальное сохранение не читается или не проходит проверку, запись блокируется. Исходные байты остаются доступны для выгрузки. Пустой новый проект не заменяет повреждённое сохранение автоматически.

Архив ограничен 100 записями; файл импорта — 5 МБ. При превышении импорт отклоняется с сохранением текущего состояния. Досье использует лимиты своего механизма событий. При переносе между разными HTML-файлами/браузерами нужно использовать JSON export/import, а не рассчитывать на общее хранилище file URL.

Исправлена обнаруженная ошибка обработчика наличия документов стоимостного расчёта: выбор документа теперь меняет соответствующий признак, а не видимость опции цели оценки. Формулы, пороги и факты производства не менялись.

## Проверки

- 16 проверок общего механизма досье.
- 15 проверок импорта и сохранения обеих версий.
- 23 проверки взаимодействия элементов собранного самостоятельного HTML: создание документа/заметки, получение ответа, закрытие, замена версии, перезагрузка, импорт, отмена, архив, отказ записи, JSON roundtrip, защита от записи отложенного файла в другой проект и защита исходного нечитабельного сохранения.
- Прежние проверки движка, индекса и контекста: 10 основных тестов, 819 регрессионных проверок, 4504 проверки индекса, 4716 проверок контекста.

Команды: npm run build:web; npm run test:tpp52; npm run test:import; npm run test:web; npm test. Для test:web нужен linkedom 0.18.12 из devDependencies. DOM_MODULES можно задать для уже установленной копии зависимости.

Проверки интерфейса выполнены через DOM. Нативная отрисовка, диалоги и выбор файлов в Chromium отдельно не подтверждены: загрузка браузерного дистрибутива в этой среде завершилась ошибкой. Это ограничение не выдаётся за пройденную визуальную приёмку.

## Что остаётся

Это работающий предварительный интерфейс досье, а не завершённая автоматическая экспертиза №52. Условные нормативные проверки и маршруты остаются заблокированными до нормативной приёмки. Непроверенные поправки №719 не активированы.

Карточки сейчас привязаны к существующим оценкам расчётного каталога. Ведение проекта по произвольной индексированной позиции без подготовленного калькулятора, включая GCV, требует следующего расширения проектной карточки. Подменять GCV насосной позицией нельзя. Синтетические названия исполнений в тестах проверяют прослеживаемость, а не соответствие реального досье РЭС.

Полные G01–G24 и T01–T16 ещё не объявляются пройденными. Следующий шаг — проект без готовой расчётной ветви и сквозная приёмка GCV; отдельно нужно завершить проверку официальных нормативных текстов. Публикация production требует решения пользователя.
