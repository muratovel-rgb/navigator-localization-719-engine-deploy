# Шаг 9.2 Проект без готового калькулятора

Дата: 15.10.2026. HTML-предпросмотр 0.8.3. Изменения подготовлены в существующем репозитории, production не публиковался.

## Результат

В общем портфеле можно создать проект по позиции поискового индекса или вручную, даже когда числовой расчёт для изделия ещё не подготовлен. Для GCV не подставляется насосная или приборная ветвь. Каталог движка остаётся прежним: 9 расчётных ветвей и 2 позиции уточнения, без нового расчётного правила.

Карточка содержит наименование проекта, заявителя/изготовителя, изделие, введённый ОКПД2, обозначение, ТУ, назначение, характеристики, даты, исполнения и кандидатов из общего индекса. Сохранённая позиция имеет статус CANDIDATE. Пустой поиск не назначает СТ-1 и не означает отсутствия требований №719.

Проект создаётся через кнопку в портфеле или из окна найденной позиции. После сохранения карточки доступны тот же модуль документов и замечаний ТПП, история, экспорт и импорт.

## Данные и прослеживаемость

Новый тип записи dossier-project хранится в существующем массиве assessments формата JSON 2. Прикладной валидатор отличает его от прежней расчётной оценки. Сам расчётный движок, его перечень правил и MCP не изменены. В dossier-project отсутствует entryId, а числовой результат явно недоступен.

Исполнения имеют постоянные ID. Документы и замечания ссылаются на эти ID; пользователь выбирает исполнения из списка. Переименование сохраняет ссылки. Удаление исполнения с историей отклоняется. Добавление исполнения не расширяет охват прежнего документа автоматически.

Изменения изделия, кода, изготовителя, исполнений или выбранных кандидатов возвращают замечания на повторную проверку. Старое решение и старая версия доказательства остаются в истории. Простое изменение названия проекта не меняет результат проверки доказательств.

Карточка имеет собственную историю редакций с автором, временем и прежними сведениями. Досье сохраняется отдельно от снимков карточки: правка реквизитов не теряет недавно добавленные документы и ответы. Незавершённые правки карточки блокируют её выгрузку до сохранения.

Импорт использует уже реализованный выбор рабочей версии и архив. Отдельная выгрузка проекта включает только его оценки, историю и архивные версии. Архивы других проектов и общий массив исходных старых импортов в неё не включаются. Полная выгрузка портфеля остаётся отдельным явным действием.

## Проверки

- 18 проверок модели проекта: отсутствие расчётной ветви, смешанный портфель, 18 исполнений, связи доказательств, изменение идентификации, повторная проверка, защита от удаления исполнения, импорт обеих редакций и сохранение исторического кандидата индекса.
- 16 проверок через DOM собранного HTML: создание GCV из поиска, отсутствие вызова калькулятора, выбор 18 исполнений, проверка охвата двух исполнений, закрытие по актуальной версии, переименование, сохранение истории, JSON roundtrip и исключение чужих архивов из индивидуальной выгрузки.
- 23 прежние проверки интерфейса, 16 проверок досье, 15 проверок импорта и прежняя регрессия движка/индекса/контекста прошли.

Для проверок использованы обезличенные сведения и синтетические файлы. Они подтверждают технический сценарий, а не происхождение продукции или юридическое соответствие реального предприятия.

Команды: npm test; npm run test:projects; npm run test:web. Для test:web требуется linkedom 0.18.12. Одна общая тестовая оболочка используется для обоих наборов DOM-проверок.

Нативная визуальная приёмка остаётся открытой: браузерный дистрибутив ранее не загрузился в этой среде. DOM-проверки не выдаются за проверку нативных диалогов, мобильной отрисовки или поведения конкретного браузера.

## Границы готовности

Полная приёмка G01–G24 не завершена. Реестр технического покрытия и пробелов сохранён в gcv-acceptance-progress.json. Не реализованы, в частности, реестр официальных заявок ГИСП, замороженная опись поданного пакета и отдельные официальные результаты акта/реестровой записи. Проверка происхождения по цепочке поставок и адресные запросы пока требуют дальнейшего расширения интерфейса.

Нормативная матрица №52 остаётся в согласованном проектном состоянии до проверки контрольных источников. Спорные даты, новые формулы и числовое правило GCV не активированы. Программа не получает полномочий эксперта ТПП и не объявляет полученную реестровую запись автоматически.
